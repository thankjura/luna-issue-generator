# luna-issue-generator

Генератор тестовых данных и стенд для замеров поиска и переиндексации Луны.

## Стенд: up → bench → down

```bash
J=target/luna-issue-generator-1.2.jar
java -jar $J up -w ~/luna-bench --set issues.count=1000000      # Луна через luna-sdk + данные
java -jar $J bench search  -w ~/luna-bench                      # правильность и скорость поиска
java -jar $J bench reindex -w ~/luna-bench -l baseline          # полная переиндексация с блокировкой
java -jar $J down -w ~/luna-bench                               # остановить Луну, данные остаются
```

`up` создаёт рабочий каталог, запускает `luna-sdk run -w DIR/luna --no-plugin` (JMX на `sdk.jmxPort`) и генерирует данные
в `DIR/data`. Повторный `up` продолжает генерацию. Луна остаётся работать после выхода. Итоговая конфигурация
сохраняется в `DIR/config.yaml`, остальные команды берут её, если не указан `-c`.

`bench` сам запускает Луну, если она не работает (`--stop` — остановить после прогона). Луну по адресу `server.url`,
запущенную не из этого каталога, команды не трогают без `--attach`.

| Путь в рабочем каталоге | Что внутри |
|---|---|
| `config.yaml` | конфигурация последнего `up` |
| `luna/` | состояние luna-sdk: luna-home (индекс в `luna-home/index`), база, Tomcat |
| `sdk.log`, `server.json` | вывод luna-sdk; запущенная Луна (pid, адрес, порт JMX) |
| `data/` | состояние генератора и `summary.json` |
| `runs/<дата>-<вид>[-метка]/` | один прогон: `report.json`, CSV с результатами, `samples.csv`, `config.yaml` |
| `runs/index.csv` | строка на прогон для сравнения (`-l` задаёт метку, например `ram-buffer-256`) |

`samples.csv` — нагрузка раз в `bench.sampleMillis`: CPU (ядер) и heap JVM Луны, паузы GC, потоки (JMX), RSS Tomcat,
CPU/load/память/диск хоста (`/proc`), CPU, память и IO контейнера PostgreSQL (`docker stats`).
В `report.json` для каждой фазы записаны средние и максимумы.

### bench search

1. Контрольные значения из `summary.json`: каждый запрос должен найти ровно ожидаемое число задач.
   Дополнительно: `=` с контрольным значением однострочных полей в верхнем регистре (поиск без учёта регистра),
   часть слова контрольного токена через `summary ~` и `text ~` (поиск по подстроке).
2. Согласованность каждого поля с поиском: `is not EMPTY` = числу задач со значением (генератор считает их),
   `is EMPTY` = остальным, для чисел и дат `< X` + `>= X` = задачам со значением. Неподдерживаемые полем операторы
   отмечаются отдельно и ошибкой не считаются.
3. Время типичных запросов по типам полей: равенство, `is not EMPTY`, сортировка, диапазон, слово, комбинированный
   запрос и свои из `bench.search.queries`.
4. Пропускная способность: `bench.search.concurrency` параллельных клиентов по `durationSeconds` секунд.

Файлы: `correctness.csv`, `consistency.csv`, `latency.csv`, `throughput.csv`.

### bench reindex

Полная переиндексация с блокировкой (`bench.reindex.repeat` раз подряд): время планирования и индексации,
задач в секунду, размер индекса, нагрузка за прогон. Ход — в `progress.csv`.

Для luna-sdk нужен Docker (PostgreSQL в контейнере) и `sdk.command` — путь к `bin/luna-sdk`, если его нет в PATH.
Лимит лицензии разработчика — 10 пользователей (см. «Ограничения»).

## generate

Создаёт пользователей, проекты со схемами, доп. поля всех типов и задачи, заполняя поля значениями.

```bash
java -jar target/luna-issue-generator-1.2.jar generate -c my-config.yaml -o data/
```

Настройки берутся слоями, каждый следующий переопределяет предыдущий:

1. `src/main/resources/generator-default.yaml` — значения по умолчанию с комментариями;
2. файл `-c`;
3. переменные окружения `LUNA_GEN_<ПУТЬ>`, сегменты через `__`: `LUNA_GEN_ISSUES__COUNT=1000000`, `LUNA_GEN_FIELDS__PER_TYPE__STRING=50`;
4. `--set путь=значение`: `--set issues.count=1000000`.

`--print-config` выводит итоговую конфигурацию. Сервер также можно задать общими опциями `-b/-u/-p`.

### Каталог `-o`

| Файл | Что внутри |
|---|---|
| `state.json` | всё созданное; повторный запуск с тем же каталогом продолжает генерацию |
| `controls.jsonl` | задачи с контрольными значениями |
| `errors.log` | неудачные запросы с телом запроса и ответом сервера |
| `summary.json` | сводка: сколько чего создано, время шагов, скорость, пользователи с паролями, контрольные запросы |

Ctrl+C / SIGTERM останавливает генерацию аккуратно: новые задачи не отправляются, запросы в работе завершаются,
состояние сохраняется, и повторный запуск не создаёт дублей.

### Контрольные значения

Для каждого поля с поиском создаются уникальные значения вне диапазона случайных (`controls.valuesPerField`),
каждое получает ровно `controls.issuesPerValue` задач. В `summary.json` в `controls` для каждого значения
записан QS-запрос и ожидаемое число задач — по ним проверяется поиск по всем типам полей.
Поля без поиска в Луне (цвет, продолжительность) только заполняются.

### Ограничения

- Лицензия разработчика из SDK разрешает 10 активных пользователей, генератор проверяет лимит заранее.
  Контрольные пользователи (`controls.valuesPerField`) создаются, только если есть поля типа `user`/`multiUser`.
- Счётчики «задач со значением» ведутся с этой версии; у данных, начатых раньше, проверка `is EMPTY` сводится
  к `EMPTY + not EMPTY = все`.
- Каждый поток держит одно соединение с БД сервера, поэтому больше `threads`, чем `maximumPoolSize`
  в `database.yml` (по умолчанию 20), смысла не имеет: лишние запросы ждут в очереди пула.
  На старых сборках Луны (до выдачи номеров задач через отдельный пул) `threads` должно быть меньше половины пула,
  иначе сервер зависает.
